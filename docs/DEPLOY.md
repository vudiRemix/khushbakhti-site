# Как опубликовать сайт «Хушбахти» без домена

> **Есть свой сервер и домен?** Тогда проще и надёжнее — [`docs/DEPLOY-SERVER.md`](DEPLOY-SERVER.md). Эта инструкция — для бесплатного хостинга Netlify + Supabase.

Сайт заработает бесплатно по адресу вида **`https://khushbakhti.netlify.app`**. Свой домен (например, `.tj`) можно подключить позже — см. последний раздел.

Всё делается в браузере, можно с телефона. Понадобятся три бесплатных аккаунта:

| Сервис | Зачем | Обязательно? |
|---|---|---|
| **GitHub** | здесь лежит код сайта | да (уже есть) |
| **Supabase** | база меню и фото: без неё админка не сохраняет изменения | да |
| **Netlify** | хостинг: показывает сайт в интернете | да |
| **Google Cloud** | автоперевод новых блюд | нет — можно переводить вручную |

### Почему Netlify, а не Vercel

- **Vercel** удобнее для Next.js, но его бесплатный тариф Hobby по правилам только для *некоммерческих* сайтов: «Hobby teams are restricted to non-commercial personal use only» ([Fair use](https://vercel.com/docs/limits/fair-use-guidelines)). Сайт ресторана рекламирует еду и услуги, то есть он коммерческий. Vercel может приостановить такой проект (посетители увидят ошибку 503). Честный вариант на Vercel — Pro за $20 в месяц.
- **Netlify Free** коммерческие сайты не запрещает: договор (Self-Serve Subscription Agreement) разрешает пользоваться сервисом и бесплатным тарифом для деловых целей. Next.js 15 поддерживается без настройки: страницы, админка, мгновенное обновление после сохранения, оптимизация фото.

### Что важно знать о бесплатном Netlify

- **300 кредитов в месяц**, денег не списывают никогда. Каждая публикация новой версии кода стоит **15 кредитов** (около 20 в месяц). Трафик и запросы тоже расходуют кредиты, маленькому ресторану обычно хватает с запасом.
- **Изменения в админке кредитов на публикацию не тратят**: меню, цены, фото и «Плов сегодня» обновляются без новой сборки.
- Если кредиты кончились, **сайт встаёт на паузу** («Site not available») до начала следующего месяца (отсчёт от даты регистрации). Письма-предупреждения приходят на 50, 75, 90 и 100 %.
- Бесплатный тариф без гарантий: Netlify вправе отключить проект. Код хранится в GitHub, меню — в Supabase, поэтому сайт можно быстро поднять заново в другом месте.

## Шаг 1. База Supabase (10 минут)

1. Зайдите на [supabase.com](https://supabase.com) → **Start your project** → войдите через GitHub.
2. **New project**: имя `khushbakhti`, придумайте пароль базы (сохраните, но сайту он не нужен).
   - **Region:** выберите **East US (Ohio)**. Бесплатный Netlify запускает серверную часть сайта в США (Огайо), и база рядом с ней работает быстрее. Гостям из Таджикистана это не мешает: готовые страницы Netlify отдаёт из ближайшего к ним узла.
   - **Data API** оставьте включённым. Галочку «Automatically expose new tables» можно не ставить: нужные права выдаёт наш SQL-файл.
   - Нажмите **Create new project** и подождите 1–2 минуты.
3. Слева **SQL Editor** → **New query**. Откройте в GitHub файл [`supabase/schema.sql`](../supabase/schema.sql), скопируйте весь текст, вставьте и нажмите **Run**. Должно появиться *Success. No rows returned*.
4. Запишите два значения (понадобятся в шаге 2):
   - **Project URL** — кнопка **Connect** вверху страницы проекта (или Integrations → Data API), вида `https://abcd1234.supabase.co`;
   - **секретный ключ** — Project Settings → **API Keys** → вкладка *Publishable and secret API keys* → **Secret keys** → скопируйте ключ `sb_secret_…` (если ключей нет, нажмите **Create new API keys**). Старый длинный ключ `service_role` (начинается с `eyJ`) тоже подойдёт, но Supabase отключает такие ключи до конца 2026 года.

> Секретный ключ даёт полный доступ к базе. Вставляйте его только в настройки хостинга, никому не пересылайте и не публикуйте.

Меню заполнять не нужно: при первом открытии сайт сам перенесёт в базу все 25 блюд.

> **Пауза бесплатной базы.** Supabase ставит бесплатный проект на паузу, если почти неделю к базе не было запросов. Сайт обращается к базе, когда его открывают гости, так что при обычной работе ресторана пауза не грозит. За неделю до паузы приходит письмо: тогда просто откройте админку сайта или панель Supabase. Если пауза всё же случилась, страницы сайта продолжат показывать последнюю сохранённую версию меню, но админка работать не будет, а фото, загруженные через админку, могут не показываться: Supabase → проект → **Resume project**. Восстановить проект можно в течение 90 дней.
>
> Бесплатная база Supabase: 500 МБ данных, 1 ГБ фото, 5 ГБ трафика в месяц. Меню ресторана занимает меньше 1 МБ, фото после сжатия — 50–150 КБ каждое. Резервные копии на бесплатном тарифе скачать нельзя, поэтому в админке есть кнопка **Настройки → Скачать копию меню**.

## Шаг 2. Хостинг Netlify (10 минут)

> Сначала код сайта должен оказаться в основной ветке `main` репозитория на GitHub (сейчас он в ветке `ccr-64abc038-gz82yr`): откройте репозиторий → **Pull requests** → **New pull request** → выберите эту ветку → **Create** → **Merge**.

1. Зайдите на [netlify.com](https://www.netlify.com) → **Sign up** → **GitHub**.
2. **Add new project** → **Import an existing project** → **GitHub**. Netlify попросит установить своё приложение GitHub: выберите **Only select repositories** → `khushbakhti-site`.
3. Выберите репозиторий `khushbakhti-site`, ветка **main**. Команду сборки и папку Netlify подставит сам (`npm run build`, `.next`) — ничего не меняйте.
4. На этой же странице нажмите **Add environment variables** и добавьте переменные из таблицы ниже. Для `SITE_URL` пока укажите `https://khushbakhti.netlify.app`.
5. **Deploy**. Сборка идёт 2–4 минуты.
6. **Дайте сайту имя**: Project overview → **Customize** → **Manage project name** → `khushbakhti`. Адрес станет `https://khushbakhti.netlify.app`. Если имя занято, возьмите другое (например, `khushbakhti-khujand`) и поправьте `SITE_URL`.
7. **Откройте сайт для всех.** Новые проекты Netlify по умолчанию *закрыты*: без этого шага гости увидят просьбу войти в Netlify. Project configuration → General → **Visitor access** → **Project visibility** → **Public** (или кнопка **Make public**).
8. По желанию уберите значок «Powered by Netlify» в углу страниц: Project configuration → General → **Powered by Netlify badge** → выключить.

### Переменные окружения

| Имя | Значение | |
|---|---|---|
| `ADMIN_PASSWORD` | пароль для входа в админку: не короче 12 символов, лучше 3–4 случайных слова (например `чайник-гранат-ветер-17`). Не используйте номер телефона и название ресторана | обязательно |
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL из шага 1 | обязательно |
| `SUPABASE_SECRET_KEY` | секретный ключ `sb_secret_…` из шага 1 | обязательно |
| `SITE_URL` | адрес сайта, например `https://khushbakhti.netlify.app` (без `/` в конце) | обязательно |
| `GOOGLE_TRANSLATE_API_KEY` | ключ переводчика из шага 3 | по желанию |
| `SESSION_SECRET` | любая длинная случайная строка | по желанию |

Где менять потом: Project configuration → **Environment variables**. После любого изменения переменных сайт нужно **пересобрать**, иначе изменения не вступят в силу: **Deploys** → **Trigger deploy** → **Deploy project** (это 15 кредитов).

## Шаг 3. Автоперевод Google (по желанию, 15 минут)

Без ключа сайт работает: у всех 25 блюд переводы уже есть и проверены. Для новых блюд переводы на таджикский, английский и китайский тогда вводятся вручную в админке.

**Важно до начала.** Google Translate работает только с подключённой банковской картой, даже в пределах бесплатного объёма. Бесплатно — **500 000 символов в месяц**, этого хватает на сотни блюд (перевод одного блюда на три языка — около 200–500 символов). Дальше — $20 за миллион символов. Чтобы не получить счёт, в пункте 6 ставится жёсткий дневной лимит.

1. Откройте [console.cloud.google.com](https://console.cloud.google.com) → создайте проект `khushbakhti`.
2. **Billing** → привяжите платёжный аккаунт с картой. Если Google предложит пробный период (Free Trial, $300 на 90 дней), после него аккаунт нужно перевести на обычный (**Upgrade**/**Activate full account**), иначе через 90 дней переводчик перестанет работать. Бесплатные 500 000 символов в месяц останутся.
3. Включите API: [Cloud Translation API → Enable](https://console.cloud.google.com/apis/enableflow?apiid=translate.googleapis.com).
4. **APIs & Services** → **Credentials** → **Create credentials** → **API key**. В ограничениях ключа (**API restrictions** → **Restrict key**) отметьте только **Cloud Translation API** → **Save**. Скопируйте ключ.
5. В Netlify добавьте переменную `GOOGLE_TRANSLATE_API_KEY` с этим ключом и пересоберите сайт.
6. **Лимит, чтобы не платить:** IAM & Admin → [Quotas](https://console.cloud.google.com/iam-admin/quotas) → найдите *Characters sent to general model per project per day* → **Edit** → `15000`. Это ≈ 465 000 символов в месяц — меньше бесплатного объёма. Если лимит кончится, сайт просто сохранит блюдо без перевода. Лимит сбрасывается в полночь по тихоокеанскому времени (утром по Худжанду), а новое значение начинает действовать в течение суток.
7. По желанию: **Billing** → **Budgets & alerts** → бюджет $1 только для Cloud Translation — придёт письмо, если что-то пойдёт не так. Бюджет сам расходы не останавливает, их останавливает лимит из пункта 6.

Переводы, сделанные автоматически и ещё не проверенные, отмечены на сайте звёздочкой, а рядом стоит подпись «Powered by Google Translate» — этого требуют условия Google. Когда проверите перевод в админке (**Отметить «проверено»**), звёздочка исчезнет.

## Шаг 4. Проверка после публикации

1. Откройте `https://<адрес>/admin` → войдите паролем `ADMIN_PASSWORD`.
   - Нет красной плашки «Изменения не сохраняются» — база подключена.
   - Нет жёлтой плашки «Автоперевод выключен» — переводчик подключён.
2. Переключите «Плов сегодня» и откройте главную сайта на телефоне: статус изменится сразу.
3. Откройте любое блюдо → **Заменить фото** → снимите блюдо телефоном → **Сохранить и перевести**. Фото уменьшится и обрежется до квадрата само.
4. **QR** → укажите число столов → **Печать**. Коды ведут на `SITE_URL/t/<номер стола>`: меню откроется на языке телефона гостя, а номер стола попадёт в «Мой стол».

> Печатайте QR только после того, как адрес сайта окончательный. Если позже появится домен, старый адрес `*.netlify.app` продолжит работать и перенаправлять гостей.

## Как работает админка

| Что | Где |
|---|---|
| Плов закончился / снова есть | главная админки, большой переключатель |
| Блюдо закончилось | переключатель рядом с блюдом |
| Цена, название, описание, фото, «Новинка», «На главной» | нажмите на блюдо |
| Переводы | в карточке блюда: статус у каждого языка, кнопки «Отметить „проверено“» и «Перевести заново». Исправленный вручную перевод автоматически не перезаписывается |
| Часы, телефон, доставка, адреса, ссылки | **Настройки** |
| QR-коды столов | **QR** |
| Резервная копия меню | **Настройки** → **Скачать копию меню** (раз в месяц) |

Изменения появляются на сайте сразу после сохранения. Вход в админку запоминается на 30 дней; чтобы выйти на всех устройствах, смените `ADMIN_PASSWORD` (и `SESSION_SECRET`, если задавали) и пересоберите сайт.

## Если что-то не работает

| Что видно | Что делать |
|---|---|
| Гости видят просьбу войти в Netlify | Проект закрыт: шаг 2, пункт 7 (**Make public**) |
| «Site not available» | Кончились кредиты Netlify: сайт вернётся в начале следующего месяца. Проверьте Team → **Billing / Usage** |
| Сборка не запустилась, статус **Pending approval** | Если репозиторий приватный, Netlify ждёт одобрения коммитов от авторов не из команды. **Deploys** → откройте сборку → **Approve** |
| Сборка упала (**Failed**) | **Deploys** → сборка → лог. Чаще всего это опечатка в переменных окружения |
| В логе сборки «Error occurred prerendering page» или «Supabase: …» | Во время сборки сайт читает меню из Supabase. Проверьте, что проект Supabase не на паузе (**Resume project**), выполнен `schema.sql` и ключи скопированы без пробелов. Затем **Deploys** → **Retry** |
| В админке красная плашка «Изменения не сохраняются» | Не заданы `NEXT_PUBLIC_SUPABASE_URL` или `SUPABASE_SECRET_KEY`. Добавьте и пересоберите |
| Админка пишет «Что-то пошло не так» | Пропал интернет, не выполнен `supabase/schema.sql` (шаг 1, пункт 3) или проект Supabase на паузе (см. шаг 1). Подробности — Netlify → **Logs** → **Functions** |
| «Пароль слишком короткий» на входе | `ADMIN_PASSWORD` должен быть не короче 12 символов |
| Фото не загружается | Выберите фото поменьше или сделайте снимок заново. Если не помогает — **Logs** → **Functions** в Netlify (логи хранятся сутки) |
| QR-коды ведут не туда | Проверьте `SITE_URL`, пересоберите сайт и распечатайте коды заново |

## Свой домен позже

1. Купите домен у регистратора (для `.tj` — аккредитованные регистраторы зоны TJ).
2. Netlify → Project → **Domain management** → **Add a domain** → следуйте подсказкам (запись DNS у регистратора или перенос DNS в Netlify). HTTPS-сертификат Netlify выпустит сам и бесплатно.
3. Поменяйте `SITE_URL` на новый адрес и пересоберите сайт.
4. Адрес `*.netlify.app` после подключения домена продолжает работать, поэтому уже напечатанные QR-коды не сломаются. Новые коды печатайте уже с доменом.

## Для разработчика

```bash
npm ci
cp .env.example .env.local   # можно оставить пустым: будет файл data/store.json и пароль khushbakhti
npm run dev                   # http://localhost:3000, админка — /admin
npm test && npm run lint && npm run typecheck && npm run build
```

- Без переменных Supabase данные хранятся в `data/store.json`, фото — в `public/uploads/` (оба в `.gitignore`). На хостинге этот режим только для чтения.
- Начальное меню — `data/menu.json` и `src/lib/seed.ts`. Если база Supabase пустая, сайт заполняет её из них сам.
- Временные фото блюд — `public/photos/temp/`, авторы и лицензии — `data/photo-credits.json` (страница «Фото» на сайте). Когда загружаете своё фото, подпись автора убирается автоматически.
