> Дизайн-система: [`docs/DESIGN.md`](DESIGN.md). Логотип: `public/brand/`. Меню: [`data/menu.json`](../data/menu.json).

## 1. Цели

- Гость с телефона за 1–2 нажатия видит меню **на своём языке**: русском, таджикском, английском или китайском.
- Администратор обновляет меню, цены, фото и наличие блюд сам, без разработчика.
- Переводы блюд делаются **автоматически** при сохранении; администратор только проверяет и при необходимости правит их.

Вне первого релиза: онлайн-заказы и оплата, доставка, бронирование столов.

## 3. Автоперевод

1. Администратор вводит блюдо **на русском** (исходный язык).
2. При сохранении сервер отправляет название и описание в **Google Cloud Translation API** на `tg`, `en`, `zh-CN`.
3. Переводы сохраняются в базе со статусом `auto`. На сайте ничего не переводится «на лету», поэтому страницы быстрые.
4. Перевод повторяется, только если русский текст изменился (сравниваем хеш исходника).
5. Переводы со статусом `manual` (исправлены вручную) автоматически **не перезаписываются**.
6. Если перевода нет, показывается русский текст.
7. **Словарь «не переводить»**: названия национальных блюд (плов, кенча, шурпа, кавурдок, чазза…) задаются вручную один раз, чтобы машинный перевод их не искажал.
8. Интерфейс сайта (кнопки, заголовки) переводится один раз вручную в файлах `messages/{ru,tg,en,zh}.json`.

**Риск:** машинный перевод на таджикский заметно слабее, чем на английский и китайский. До начала разработки проверяем его качество на 20–30 реальных блюдах. Если результат плохой, таджикский переводит носитель языка, а автоперевод оставляем для `en` и `zh`.

## 4. Стек

| Часть | Выбор |
|---|---|
| Сайт и API | Next.js (App Router) + TypeScript |
| Мультиязычность | `next-intl`, маршруты `/[locale]`, `hreflang` |
| Стили | Tailwind CSS с токенами из `docs/DESIGN.md` |
| БД, вход, фото | Supabase (Postgres + Auth + Storage) |
| Переводчик | Google Cloud Translation API (ключ только на сервере) |
| Обновление сайта | On-demand revalidation после сохранения в админке; статус «Плов сегодня» через Supabase Realtime |
| Хостинг | Vercel + Supabase |

## 5. Модель данных

```
categories            id, slug, sort, is_visible
category_translations category_id, lang, name, status(auto|checked|manual), source_hash
dishes                id, category_id, price_tjs, photo_url, tags[] (new),
                      is_available, is_signature, sort, updated_at
dish_translations     dish_id, lang(ru|tg|en|zh), name, description,
                      status(auto|checked|manual), source_hash, updated_at
glossary              term_ru, term_tg, term_en, term_zh   -- «не переводить»
tables                id, number, qr_slug
settings              plov_today(bool), hours, phone, address, socials
profiles              user_id, role(admin|editor)
```

Безопасность: Row Level Security в Supabase; запись только для `admin`/`editor`; ключ переводчика и сервисный ключ Supabase только на сервере.

## 7. Идеи на второй этап

- **Telegram-бот для администратора**: «/плов закончился», «/нет пахлавы» прямо из кухни, без входа в админку.
- **Блюдо дня** с отдельным блоком на главной.
- **Работа при слабом интернете** (PWA): меню кэшируется и открывается даже при плохой связи.
- Бронирование столов и отзывы гостей.

## 8. Что нужно от ресторана

Уже есть: меню с ценами, логотип (очищен, в `public/brand/`), адрес, телефон, Instagram.

Ещё нужно:
- Часы работы.
- Фото блюд и зала (лучше одна фотосессия в едином стиле).
- Векторный логотип (SVG/PDF/AI), если он есть у дизайнера; для печати и вывесок.
- Короткие описания блюд (состав), если хотите их на сайте.
- WhatsApp / Telegram, если есть.
- Кто будет администратором (email).

4. Китайский — упрощённые иероглифы (`zh-CN`)? Предполагаем да.
5. Готов ли ресторан к ручной проверке таджикского перевода носителем языка?
